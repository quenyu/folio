# Domain docs

This is a single-context repository. Engineering skills should read `CONTEXT.md` and relevant records under `docs/adr/` when those files exist.

Use terminology defined in `CONTEXT.md` consistently in issues, tests, code, and review findings. If required domain documentation is absent, proceed silently; create it only when a real terminology or architectural decision needs to be recorded.

If proposed work conflicts with an existing ADR, surface the conflict explicitly instead of silently overriding the recorded decision.
